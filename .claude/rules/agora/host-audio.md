## Agora Host Audio (the SDK default is *nothing*, and Android hears it as a phone call)

**`AgoraRTC.createMicrophoneAudioTrack()` with no config publishes Opus at Chrome's default (~32 kbps, adaptive downward) through Android's *voice-call* capture chain.** Same shape of defect as the 4:3 camera (`.claude/rules/agora/camera-aspect-ratio.md`), and it produced the same kind of report: "sounds dull, like a telephone, even recorded with professional gear". The host's track now carries `AGORA_MIC_ENCODER_HOST` (`high_quality` — 48 kHz mono 128 kbps) plus `AGORA_MIC_NO_PROCESSING`, both in `client/lib/constants.js`, chosen by role in `AgoraLiveRoom` exactly like `cameraEncoderConfig`.

* **The documented default does not exist.** The API reference says *"The SDK uses `music_standard` by default"*, but the track constructor does `super(e, t.encoderConfig ? Uk(t.encoderConfig) : {}, ...)` — `_encoderConfig` is `{}` — and the SDP munging writes each Opus parameter under its own guard (`r.bitrate && ...`, `r.sampleRate && ...`, `r.stereo && ...`). **None is written**: no `maxaveragebitrate`, no `maxplaybackrate`, no `stereo`. The `channelCount`/`sampleRate` capture constraints sit behind the same `if (e.encoderConfig)`, so omitting it also leaves capture entirely to the browser. Verified in the installed bundle, not inferred.
* **On Android, `AEC: false` does not disable a filter — it changes the capture path.** Chromium picks the input preset off that single bit (`media/audio/android/aaudio_stream_wrapper.cc`): `AAUDIO_INPUT_PRESET_VOICE_COMMUNICATION` when echo cancellation is requested, `GENERIC` otherwise (`opensles_input.cc` does the same with `CAMCORDER`). `VOICE_COMMUNICATION` is the band-limited chain Android reserves for calls. The same comment carries the second effect: `GENERIC` exists *"to ensure standard audio routing (e.g. prioritizing USB or wired headsets over the internal phone microphone)"* — **with echo cancellation on, the phone can end up broadcasting from its own internal mic instead of the USB receiver, and nothing says so.** Of the three flags, only `AEC` moves the Android preset; `ANS`/`AGC` drive Chrome's software stages.
* **Turning this up costs nothing.** Agora bills audio at $0.99/1,000 min **flat** — no tiers for bitrate, sample rate or channels, unlike video (3.99 → 8.99 at the Full HD boundary, which is why 720p is the video default). The delta is ~96 kbps of uplink beside 2–4 Mbps of video.
* **The default is fidelity; `events.host_echo_cancellation` (INTEGER, `NOT NULL DEFAULT 0`) is the escape hatch**, checkbox «El host escuchará a los invitados por altavoz», shown only for `provider='agora'` + `interaction_mode='broadcast'`. `0` means *no processing*, i.e. the good path. The default was chosen on the asymmetry of the two mistakes, not on caution: forgetting to tick it in an interactive event gives **echo** — audible instantly, fixable live with headphones — while leaving 3A on in a conference gives a whole event that sounds like a phone, **which the host cannot hear** (nobody monitors their own stream) and which is discovered afterwards. One costs seconds, the other costs the recording.
* **With the flag on, the three keys are OMITTED, never passed as `true`.** They are not equivalent: `pN() && e.ANS && (t.googHighpassFilter = e.ANS)` — passing `ANS: true` explicitly adds a high-pass filter the default path does not. Omitting reproduces the previous behavior byte for byte.
* **`meeting` is carved out for everyone, host included.** Up to seventeen simultaneous audio publishers with open laptop speakers; removing the host's AEC would couple the whole room. The encoder profile still applies there — bitrate and processing are independent axes. **Attendees and promoted speakers are untouched in both modes**: it is *their* AEC that stops them hearing themselves delayed through the host, and 128 kbps on a built-in laptop mic is wasted uplink.
* **The audio profile is frozen at track creation.** `ILocalAudioTrack` exposes only `setVolume` and `getVolumeLevel` — there is **no `setEncoderConfiguration` for audio**, unlike video. So no live selector is possible, and toggling the checkbox mid-event does nothing until the track is recreated (a reload). Toggling the mic off/on reuses the track (`setEnabled`), so the profile is stable for the session.
* **Changing microphone preserves it, and that is the opposite of the camera.** `setDevice` rebuilds from `this._constraints` (`n.audio = hM({}, this._constraints)`), so profile and 3A survive a device switch. Do not add a "reapply" for audio: it is unnecessary and impossible.
* **Mono, deliberately, and it is not an Agora limit.** Chrome on Android captures mono: `audio_manager_android.cc` picks the input layout off `features::kAudioStereoInputStreamParameters`, which is `FEATURE_DISABLED_BY_DEFAULT` in `media/audio/audio_features.cc` — still an open experiment. Requesting a stereo preset would also push `channelCount: 2` against mono-forced params. And two lavaliers hard-panned L/R are not stereo but two discrete monos: fatiguing on headphones, and the pathological case for Opus's Mid/Side coding. The numbers agree — `standard_stereo` is ~32 kbps per channel against 128 for mono `high_quality`. **Stereo at full quality exists only off a laptop** (desktop Chrome captures stereo with AEC off, and `high_quality_stereo` at 192 kbps is the highest ceiling of any path, above the native Android SDK's 128) — a separate product decision, deliberately not built here.
* **Operational procedure, which no code can enforce:**
  * **The wireless receiver goes in Mono mode**, with one transmitter and with two. In Stereo mode a single transmitter leaves one channel silent and the downmix to mono costs ~6 dB of level — which reads as "dull" and then gets compressed back up. Two speakers are summed **in the receiver**, with their gains matched there; never panned.
  * **Whenever the host will give the floor to guests, the return audio goes to an earpiece, not a room speaker.** AEC over an external USB device, with the phone metres away on a tripod, is unreliable on Android anyway. The checkbox is the fallback for when a closed return is impossible, not the normal route.
  * For concerts: set gain low by hand (there is no AGC), record locally on the transmitters as the master, and use the video quality selector to drop to 480p when the venue uplink is poor — audio is what should survive.
* **Known blind spot:** the client still has no test runner, so the per-role composition is verified by hand on device. The API half (column, validators, persistence) is covered by `api/tests/eventHostFlags.test.js`, which runs the same six cases over each of the three host flags.
